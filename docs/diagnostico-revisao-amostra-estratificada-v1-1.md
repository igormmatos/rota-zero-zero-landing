# Revisão estratificada — V1 × candidato D

**Status:** pesquisa. Não altera o motor de produção.

**Base comparada:** `R00-DIAG-1.0.0` × `D_AGENCY_REPRESENTATION`.

**Objetivo:** revisar manualmente perfis que mudam entre V1 e D e pares de fronteira que ainda geram saltos `02→04`, usando como referência primária o significado editorial das etapas no Livro-fonte V2.1 e no Documento-base.

---

## 1. Regra de interpretação usada nesta revisão

A revisão não trata `00→04` como uma escala psicométrica linear.

As fontes canônicas do projeto dizem que:

- a sequência é **flexível** e é uma decisão editorial, não uma lei natural;
- prontidão é uma **combinação de sinais observáveis**;
- alguém pode dispensar partes da sequência quando já demonstra autonomia, interesse e capacidade de sustentar investigação;
- a Etapa 04 existe para **conectar interesse → projeto → tecnologia**;
- o critério editorial do Documento-base para a Etapa 04 é conseguir **escolher um próximo projeto e um recurso adequado ao objetivo**;
- uma criança pode estar pronta para um projeto visual e ainda não para uma trilha textual longa.

Consequência: um salto numérico `02→04` não é, por si só, um erro. É preciso perguntar se a pessoa está pronta para uma **decisão de rota**, não se “pulou dois níveis de habilidade”.

---

O candidato D altera **1.092 de 46.656 cenários** em relação à V1.

- `04→03`: **678** cenários;

Q7 foi mantido em `I_WEB` sempre que possível porque interesse não deve alterar stage.

# 3. Perfis `04→03` — D é mais conservador

## D01 — sem projeto definido

`E3 / P0 / S2 / M3 / D3 / R3`

- V1: `04`
- D: `03`
- Motivo de D: falta `P3`.
- Julgamento: **D melhor**.

Uma pessoa sem projeto definido não corresponde bem ao significado editorial de 04, que liga interesse, projeto e tecnologia. Há competência técnica suficiente, mas ainda falta o objeto da decisão de rota.

## D02 — apenas área de interesse

`E3 / P1 / S2 / M3 / D3 / R3`

- V1: `04`
- D: `03`
- Julgamento: **D melhor**.

Saber que gosta de “web”, “jogos” ou outra área ainda não equivale a conseguir escolher um próximo projeto e um recurso coerente com ele.

## D03 — ideia concreta ainda não reduzida

`E3 / P2 / S2 / M3 / D3 / R3`

- V1: `04`
- D: `03`
- Julgamento: **D pode estar conservador demais**.

Aqui existe projeto concreto. O Livro-fonte privilegia reduzir a ideia a uma menor versão, mas o critério editorial da Etapa 04 não exige explicitamente que essa redução já esteja concluída. `P2` pode ser suficiente para começar a escolher uma rota e usar a própria rota para reduzir o projeto.

**Fila de revisão:** testar `P2 ou P3` como condição de route readiness, sem alterar learning stage.

## D04 — falta “agência forte” segundo D

`E3 / P3 / S2 / M2 / D3 / R3`

- V1: `04`
- D: `03`
- Motivo de D: não possui `E4` nem `M3`.
- Julgamento: **D parece rígido demais**.

A pessoa já define projeto mínimo, estrutura passos, modifica sozinha, investiga erros e escreve um pequeno programa. Exigir necessariamente projeto concluído (`E4`) ou transferência (`M3`) não decorre do critério editorial de 04 e transforma dois sinais fortes em requisitos universais.

## D05 — histórico de tutorial, mas prática atual forte

`E1 / P3 / S3 / M2 / D3 / R3`

- V1: `04`
- D: `03`
- Julgamento: **D parece rígido demais**.

Q1 registra histórico, enquanto Q3–Q6 registram capacidades atuais mais fortes. Dar peso absoluto a `E4 ou M3` pode deixar um dado histórico vencer evidências atuais de prontidão.

## D06 — projeto próprio, sem S3/R3

`E4 / P3 / S2 / M2 / D3 / R2`

- V1: `04`
- D: `03`
- Motivo de D: falta “profundidade de representação” (`S3 ou R3`).
- Julgamento: **D provavelmente rígido demais**.

Há projeto próprio concluído, projeto mínimo definido, estrutura, autoria e depuração forte. O requisito `S3 ou R3` é útil como evidência adicional, mas não está estabelecido pelas fontes do projeto como condição necessária para escolher uma rota.

## D07 — sem agência forte e sem profundidade adicional

`E3 / P3 / S2 / M2 / D3 / R2`

- V1: `04`
- D: `03`
- Julgamento: **D é defensável como escolha conservadora**.

É o caso mais próximo de uma fronteira real. Há boa capacidade, mas nenhum sinal mais exigente de conclusão, transferência ou previsão de consequências. Manter em 03 pode ser prudente, desde que o resultado permita explorar rotas sem tratar 04 como “nível bloqueado”.

## D08 — conflito forte resolvido por TB positivo

`E0 / P3 / S2 / M2 / D3 / R3 / TB=T2`

- V1: `04`
- D: `03`
- Julgamento: **D melhor**.

“Não criou nada” conflita com autoria independente e escrita confortável. Mesmo após TB positivo, um resultado mais conservador é apropriado até a inconsistência ser melhor compreendida.

## D09 — conflito forte e projeto ainda não reduzido

`E0 / P2 / S2 / M2 / D3 / R3 / TB=T2`

- V1: `04`
- D: `03`
- Julgamento: **D melhor**.

Acumula conflito de autorrelato com projeto ainda não reduzido. Não é um caso adequado para promoção automática a 04.

### Síntese dos `04→03`

O ganho mais convincente de D é exigir que exista projeto suficientemente concreto antes de ativar decisão de rota. Porém, `P3` como requisito universal parece mais forte do que as fontes exigem, e os hard gates `E4 ou M3` + `S3 ou R3` criam nova rigidez que não está sustentada como necessária.

# 5. Os 180 saltos `02→04` restantes

A auditoria experimental tratou “salto >1” como sinal de risco estrutural. A revisão manual mostra que esse indicador precisa ser reinterpretado.

## B01 — Q3: S1→S2

Base:

`E1 / P3 / M3 / D2 / R3`

Mudança:

- antes: `S1_PARTS_HELP` → D=`02`
- depois: `S2_STEPS_RULES` → D=`04`

**Julgamento:** o salto numérico parece grande, mas a pessoa já possui projeto mínimo, transferência, debugging sistemático e escrita. S2 apenas completa o conjunto de sinais. Não é necessariamente um erro pedagógico; é um efeito de representar “decisão de rota” como etapa ordinal.

## B02 — Q3: mesmo corte com experiência visual prévia

`E2 / P3 / S1→S2 / M3 / D2 / R3`

**Julgamento:** mesma conclusão. A fronteira merece atenção sem ser automaticamente proibida.

## B03 — Q4: M1→M2

`E4 / P3 / S2 / M1→M2 / D2 / R3`

**Julgamento:** autonomia é central, mas scaffolding é contínuo. Fazer `M1→M2` sozinho mover o resultado de 02 a 04 evidencia que duas decisões diferentes estão acopladas: posição de aprendizagem e prontidão para escolher rota.

## B04 — Q4 em perfil visual

`E4 / P3 / S3 / M1→M2 / D2 / R1`

**Julgamento:** a promoção para uma rota visual pode fazer sentido assim que há autonomia suficiente. O problema não é “pular 03”; o problema é chamar 04 de nível posterior se 04 é, funcionalmente, uma bifurcação.

## B05 — Q5: D1→D2 sem representação confortável

`E1 / P3 / S3 / M3 / D1→D2 / R0`

**Julgamento:** **suspeito**. Embora a pessoa tenha transferência e estrutura, Q1 e Q6 sugerem pouca prática consolidada. Um único avanço em debugging não deveria esconder essa incerteza. Esse caso pede regra de confiança ou revisão de coerência, não apenas Gate04.

## B06 — Q5: D1→D2 com experiência visual

`E2 / P3 / S3 / M3 / D1→D2 / R1`

**Julgamento:** muito mais plausível. A pessoa tem prática visual, projeto mínimo, previsão e transferência; D2 pode ser o último sinal necessário para liberar escolha de rota.

### Conclusão sobre os saltos

**Minimizar saltos `02→04` não deve ser objetivo primário da V1.1.**

O roadmap diz expressamente que a sequência é flexível. Se 04 significa “escolher um caminho real”, então alguém pode estar aprendendo de forma visual e já estar pronto para escolher uma rota visual. Penalizar esse caso apenas porque “não passou por 03” reintroduziria a rigidez que o Livro-fonte rejeita.

# 6. Achado arquitetural principal

A amostra mostra que o problema central não está apenas no conteúdo de Gate04.

A arquitetura atual mistura duas perguntas diferentes:

1. **Onde a pessoa está aprendendo melhor agora?**
2. **Ela já tem evidência suficiente para escolher uma rota de projeto/tecnologia?**

Hoje, ambas são comprimidas em um único `stage` de `00` a `04`.

Isso faz 04 parecer um nível de proficiência superior a 03, embora as fontes do projeto descrevam 04 principalmente como **bifurcação por projeto**.

## Hipótese para V1.1

Separar:

```text
learningStage: 00 | 01 | 02 | 03
routeReadiness: NOT_READY | READY
interestTag: I_WEB | I_AUTOMATION | I_GAMES | I_APPS | I_AI_DATA | I_UNSURE
route: null | web | automation | games | apps | ai_data | open_exploration
```

Exemplos:

- `learningStage=02` + `routeReadiness=READY` + `route=games` é possível e coerente;
- `learningStage=03` + `routeReadiness=NOT_READY` é possível quando há escrita, mas ainda não existe projeto concreto;
- `I_UNSURE` continua legítimo e pode produzir `open_exploration` quando houver prontidão de rota.

A saída pública pode continuar simples. Não é necessário mostrar dois scores. O sistema pode dizer, por exemplo:

> Seu ponto de partida para aprender é **02 — Criar visualmente**. Você já tem sinais suficientes para escolher um projeto de **Jogos** como próxima direção.

# 7. Decisão desta fase

**Não promover candidato D diretamente para produção.**

D permanece valioso como experimento porque mostrou três coisas:

1. texto não precisa ser hard gate universal;
2. D3 não precisa ser hard gate universal;
3. projeto concreto deve participar explicitamente da decisão de rota.

Mas D também introduz hard gates novos (`E4 ou M3`, `S3 ou R3`) e herda contaminação do TB atual.

A próxima comparação deve ser **arquitetural**, não apenas uma nova fórmula de Gate04:

- manter 00–03 como eixo de aprendizagem;
- modelar readiness de rota separadamente;
- usar `P2/P3`, autoria, investigação e sinais fortes como evidência de route readiness;
- testar TB sem reescrever dimensões não conflitantes;
- comparar a nova arquitetura com V1 nos mesmos 46.656 cenários.

---

## 8. Critério para próxima rodada

Uma alternativa será considerada melhor se:

- preservar os invariantes de interesse e contexto;
- não exigir texto para todas as rotas;
- não transformar consulta a fonte em requisito de debugging;
- não inferir autoria/debugging a partir de TB sobre outro conflito;
- permitir rota visual sem exigir passagem artificial por escrita;
- exigir projeto suficientemente concreto para uma decisão de tecnologia;
- manter explicabilidade em linguagem de pais;
- continuar sendo apresentada como orientação, não avaliação psicométrica.
